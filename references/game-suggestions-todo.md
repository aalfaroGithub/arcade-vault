## Protocolo de concurrencia

Este archivo es **una sola tabla, una fila por candidato**. Varias instancias
de `game-planner` pueden correr en paralelo porque la unidad de escritura es
la fila, no el archivo:

- Cada instancia genera un id propio `gp-YYYYMMDD-xxx` y lo escribe en la
  columna `Instancia` de cada fila que toca.
- Antes de evaluar un candidato, la instancia lo **reclama**: crea la fila (o
  pasa `pendiente` → `evaluando`) con sus criterios en `–`. Si el `Edit`
  falla o el candidato ya aparece `evaluando` de otra instancia, se cede y se
  reporta como "en curso por `<instancia>`".
- Solo se edita una fila propia (`evaluando` con la propia `Instancia`) o una
  fila `pendiente`/inexistente que se acaba de reclamar. Nunca se toca una
  fila `evaluando` ajena.
- Puede haber varias filas en `recomendado` a la vez (una por instancia) — el
  desempate es del usuario u otra corrida, ordenando por `Total`.
- `Write` sobre este archivo solo si no existe o está vacío; toda
  actualización posterior es `Edit` de una fila puntual.
